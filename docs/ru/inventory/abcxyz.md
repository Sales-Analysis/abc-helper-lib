# ABC-XYZ

Назад к [товарным анализам](../inventory.md)

## Назначение

ABC-XYZ объединяет важность по выручке и стабильность спроса в одну составную
классификацию, например `AX` или `CZ`.

## Когда использовать

- когда решения по ассортименту зависят и от contribution, и от predictability;
- когда нужен компактный grid для политики пополнения или планирования.

## Когда не использовать

- когда важна только одна ось, а вторая будет лишним шумом;
- когда value- и demand-данные относятся к разным наборам товаров.

## Вход

- все поля, нужные для `ABC`
- все поля, нужные для `XYZ`
- опциональные ABC-пороги
- опциональные XYZ-пороги

## Выход

- основные поля из `ABC`
- основные поля из `XYZ`
- `CombinedGroup`, например `AX`, `BY`, `CZ`

## Правила

- пакет независимо запускает `ABC` и `XYZ`
- результаты объединяются по `OriginalIndex`
- `CombinedGroup = ABCGroup + XYZGroup`

## Пример

```go
out, err := analytics.New().Inventory().ABCXYZ(ctx, abcxyz.Input{
    Items: []abcxyz.Item{
        {SKU: "A", Name: "Item A", Quantity: 10, Price: 100, Demands: []float64{10, 12, 9}},
    },
})
```

## Интерпретация

`AX` обычно означает стратегически важный и стабильный товар. `CZ` обычно
означает низкий вклад и волатильный спрос.

## Частые ошибки

- ожидать, что пакет сам выведет demand из quantity и price;
- передавать несогласованные наборы value- и demand-данных;
- забывать, что итоговый порядок следует сортировке `ABC`.
